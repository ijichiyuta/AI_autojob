# 要件定義からの変更点

元の要件定義（2026-09-12）に対し、実装前の調査で判明した事実に基づいて変更した箇所。
元文書は `docs/requirements.md`。

---

## 1. 追加した除外条件

### 1.1 動画・切り抜き系の絶対NG ★最重要

**元の要件定義にない。** BACKSTAGE業務委託契約 第8条（競業避止）により、契約期間中はBS以外から
切り抜き動画に関する業務を受託できず、違反時の違約金は固定報酬12ヶ月分 = **246万円**。

対応:
- `ng_rules.video_noncompete`（9パターン）で案件文から検出
- `jobs.category = 'video'` を無条件でNG
- `blocked_groups` で収集対象グループから除外（`video_contents` / `sounds` / `multimedia` / `3dcg`）

### 1.2 稼働量オーバー（`capacity_excess`）

本人の可処分時間は**週20時間＝月約87時間**。初回クロールで上位を占めた「クラウドワークス テック」の
出稿は、いずれも「毎月の稼働時間：160時間程度」の常駐型で、成立しない。

### 1.3 プラットフォーム外への応募誘導（`external_application`）

同じ出稿群は「クラウドワークス内のメッセージ返信や応募機能を使ったご相談にはお答えできかねます」と明記し、
応募を `tech.crowdworks.jp` に誘導する。自動応募の対象外であり、実態はエージェントの集客。

## 2. 緩和した条件

### 2.1 時給換算の下限は Phase 1 では除外に使わない

元の要件定義では即時除外の条件に「時給換算が設定値未満」が入っていたが、分母の `estimated_hours` は
LLM推定であり初期は精度が出ない。これで `ng_filtered` に落とすと、**Phase 1 の目的（スコア上位の案件が
十分な数あるかを見て投資判断する）そのものが歪む**。

対応: Phase 1 では警告フラグに留め、一覧には残す。実績データが溜まってから絶対条件に昇格させる。

### 2.2 実績獲得モード（`bootstrap_mode`）

本人のクラウドワークス実績は「あまりついていない」。評価ゼロでは3万円以上の案件は通りにくいため、
初期は予算1万円・時給1,500円まで下限を緩めて評価を取りにいく。完了5件で通常の閾値に戻す。

## 3. 設計の変更

### 3.1 Chromeプロファイルは専用のものを切る

元の要件定義は「普段使いのChromeプロファイルを指定する」としていたが、Chromeはプロファイル
ディレクトリを排他ロックするため、**ワーカーが掴んでいる間は普段のChromeが開けず、逆も同じ**。
1日4回のバッチのたびにブラウザが使えなくなる。

対応: `.chrome-profile/` を専用に切り、初回のみ手動ログイン（2FAもその一度きり）。
セッション保守が不要という元の狙いはそのまま満たせる。実際に実装中、収集バッチ実行中に
別コマンドを起動して `ProcessSingleton` エラーを踏んでおり、この判断は正しかった。

### 3.2 ブラウザは常駐させない

`headless: false` のブラウザを常時起動はしない。常駐するのは node-cron のプロセスだけで、
バッチごとに起動→終了する。スリープ対策は `caffeinate`。
なお、実測ではヘッドレスでもブロックされなかったため、収集は `headless: true` を既定にしている
（`--headed` で目視確認に切り替えられる）。

### 3.3 LLM判定をワーカーから切り離す

本人の方針で Claude API は当面使わない（Claude Code 側で実行する）。
ワーカーは機械的に判定できる範囲（正規表現NG・予算・応募数・クライアント評価・納期）までを処理し、
`job_scores.llm_status = 'pending'` を立てて止める。
スコアは**取得できた重みで正規化した暫定値**とし、`breakdown._meta.provisional` で暫定であることを残す。

### 3.4 詳細取得は一次フィルタ通過後のみ

システム開発グループだけで8,000件あるため、全件の詳細を取るとリクエストが膨れる。
一覧の情報（タイトル・抜粋・カテゴリ・予算）でNG判定と予算足切りを先に行い、通過したものだけ詳細に行く。
NG除外された案件は詳細ページへのリクエストを1回も使わない。

### 3.5 対象はクラウドワークスのみ

ランサーズは利用規約 第31条1項15号（サイトのコンテンツを複製・二次利用して営利目的で使うことの禁止）の
文言が広く、案件文をDBに保存する行為がグレーになりうる。Phase 1 では対象外とする。

**クラウドワークス側の確認結果**: 利用規約 第23条（禁止事項）に自動化・スクレイピング・ボットを
名指しした条項は**ない**。関連するのは第12号（DOS攻撃等で運営に支障を与える行為）のみで、
禁じているのは負荷であって自動化そのものではない。ガードレール（1ページ3〜8秒待機・並行アクセスなし・
1日4回のバッチ・深夜停止）は元の要件定義どおり維持する。

## 4. スキーマ上の差分

| 元の定義 | 実装 | 理由 |
|---|---|---|
| `applications.status` に全ステートを持つ | `jobs.status`（discovered/scored/ng_filtered/promoted）と `applications.status`（pending_apply以降）に分割 | 応募前の案件に applications 行を作りたくないため |
| `job_scores.ng_flags` のみ | `ng_flags` + `warn_flags` を分離 | 除外と警告を区別するため（2.1） |
| — | `job_scores.llm_status` / `llm_specificity` / `llm_genre_match` / `llm_hours` | LLM判定を後段に分離したため（3.3） |
| — | `crawl_runs` / `alerts` テーブル | 非機能要件のログ・アラートの受け皿 |
| — | `settings` テーブル | NGルール・重み・閾値をコードでなくDBに置くため |

## 5. プロフィールまわりの決定（2026-09-12）

### 5.1 屋号「スマートコネクト」に統一した

表示名が `videocreater`（ユーザーIDがそのまま表示されていた）のまま、Web制作を売っている状態だった。
動画案件はBACKSTAGE契約 第8条の競業避止で**絶対に受けられない**のに、その依頼を引き寄せる名前になっていた。

- 表示名 → `スマートコネクト開発`（上限12文字。「〜ウェブ開発」は13文字で入らなかった）
- 職種カテゴリ → Web制作 から **ITエンジニア**（SE / プログラマPG / AIエンジニア / 業務アプリ開発者）
  メイン職種カテゴリは1つしか選べない仕様のため、UI・UXデザイナーは外れる。幅はスキル登録で出す
- 個人のGitHub（ijichiyuta）を削除。実績リンクは `smcn-jp.com` に一本化した
  同サイトは屋号と名古屋市の記載のみで実名が出ないため、匿名運用と両立する

### 5.2 AI活用の明記を取りやめた（要件定義 5.3 の変更）

要件定義 5.3 は「プロフィールおよび応募文テンプレートに、AIツールを活用している旨を明記する」としていたが、
**本人判断でプロフィールからは削除**した（2026-09-12）。

設計原則2の中身のうち、
- 「AI使用不可と明記された案件には応募しない」→ `ng_rules` の `ai_prohibited` と LLM判定の二重化で担保している
- 「クライアントから問われた場合は正直に答える」→ 人間が対応する範囲なので変わらない

が残るため、実質的な担保は失われていない。変わったのは**先回りしての開示をやめた**点。

### 5.3 実運用中のシステムのURLは出さない

`app.smcn-jp.com` は実際のフリースクールが使っている本番システムのため、
プロフィールにもポートフォリオにもURLを載せない（本人判断）。実績としての記述は残す。

## 6. NDA締結とその影響（2026-09-12）

クラウドワークスとNDA（秘密保持契約）を締結した。NDAオプション付きの案件に応募できるようになる。

**条文で確認したこと**
- 第2条: 秘密情報に「クライアントの情報」「クライアントが発注する仕事に関する情報」が含まれる
- 第3条4項: 業務遂行上必要な範囲での複製は可。ただし複製も秘密情報として扱う義務
- 第6条: 善良な管理者の注意義務をもって管理する
- 第8条: 違反したら損害賠償
- 第9条: **終了する旨を申し入れれば終了できる**（第3・4・8・10条は終了後3年存続）
  ※事前情報では「解除できない」とされていたが、それはUI上の話で契約自体には終了条項がある
- 第10条: 東京地裁が専属管轄

**実装への影響**
案件情報をDBに保存するこのシステムは、NDA案件を扱う時点で秘密情報を保持することになる。
第6条の善管注意義務に対応するため、**ダッシュボードにBasic認証を入れた**（`dashboard/proxy.ts`）。
`DASHBOARD_USER` / `DASHBOARD_PASSWORD` が未設定のときは localhost 以外から 503 を返すので、
認証を設定しないままデプロイしても情報が漏れない。

なお実名・住所が相手に開示されるのは**クライアントと個別にNDAを結ぶ時点**であり、
CWとの締結だけでは開示されない。
